## 1 引言

### 1.1 编写目的

本文档是《武汉市土地利用时空信息服务平台》的软件需求规格说明书(Software Requirements Specification,SRS),用于明确该软件"做什么"。本文档的预期读者包括:

- **开发人员**(作者本人):作为设计、编码和测试的依据;
- **课程教师**:作为评判该课程设计是否满足考核要求的依据;
- **潜在用户**(城市规划、土地管理部门人员):了解软件功能是否符合业务需要。

### 1.2 项目背景

土地利用/覆被变化(LUCC)是城市发展研究的基础数据。武汉市作为中部地区中心城市,2000 年代以来经历了快速城镇化,建设用地扩张、耕地与林地缩减等变化显著。开展土地利用长时序监测,需要多年份、同规格、可比对的土地利用数据,并快速回答"某区域、某类用地在过去若干年间面积如何变化"这一核心问题。目前这类分析依赖专业桌面 GIS 软件与人工统计,耗时且门槛高。

本平台针对上述问题,开发一套 **Web 形态的土地利用时空信息服务平台**,将多年份土地利用数据统一入库,使普通用户通过浏览器即可:

1. 浏览多年份土地利用图,并以时间轴动画直观观察变化过程;
2. 对任意区域(框选范围或行政区)统计各地类面积;
3. 查看某类用地(如建设用地、水体)的长时序面积变化曲线。

### 1.3 术语定义

| 术语 | 说明 |
|---|---|
| 土地利用栅格 | 用规则网格(像元)记录地表覆被类型的空间数据,每个像元值为地类编码 |
| 像元 | 栅格数据的最小单元,本文档数据中一个像元代表地面 30 m × 30 m 范围 |
| 地类编码 | 用地类型的数字编号(1~7),与地类名称一一对应 |
| 空间数据库 | 支持空间数据类型(点、线、面)和空间运算的数据库,本平台采用 PostgreSQL + PostGIS |
| PostGIS | PostgreSQL 的空间扩展,提供空间数据类型与空间分析函数 |
| WebGIS | 基于 Web 的地理信息系统,浏览器端完成地图显示与交互 |
| 聚合网格 | 将 30 m 像元按规则大网格(1~2 km)分组统计后的结果数据,是平台**统计查询**的基本单元(地图展示采用直渲染,见 3.3.3) |
| 矢量瓦片 | 现代 WebGIS 的分级矢量数据服务格式(MVT/PBF),将海量空间数据按金字塔层级切分传输;本平台聚合网格的定位即"简化版矢量瓦片",见 3.3.3 |
| 行政区统计 | 以行政区划边界(面)为范围,统计该范围内各地类面积 |
| 框选统计 | 用户在地图上手绘一个矩形(或多边形),统计该范围内各地类面积 |
| 时间轴播放 | 按时间顺序自动逐期切换图层,形成"土地利用变化动画" |
| 卷帘对比 | 两期图层叠置显示,用户拖动分割线,左右分别露出两期,用于精确定位变化区域 |
| 长时序面积变化 | 某类用地(如建设用地)面积随年份变化的序列,是平台的核心分析能力 |
| CLCD | 中国年度土地覆盖数据集(China Land Cover Dataset),武汉大学制作,30 m、年度(1985-2023)、免费公开,为本平台数据源,见 3.3.1 |
| EPSG:32649 | 坐标参考系编码,即 WGS84 / UTM 投影 49 度带,武汉市栅格数据采用该坐标系(由数据源决定) |

## 2 任务概述

### 2.1 项目目标

开发一套可运行的 Web 时空信息服务平台,实现武汉市土地利用数据的在线浏览、时空动态展示、多年份对比与长时序面积变化统计。具体目标按优先级分为两级:

- **V1 目标(及格线,必须完成)**:
  1. 网页地图浏览:加载武汉市底图,支持缩放、平移;
  2. 多年份图层展示与动态对比:加载多个年份土地利用图层,支持时间轴动画播放与卷帘对比;
  3. 面积统计查询:支持两种空间查询方式(框选范围、行政区),以表格和图表返回各地类面积、占比及长时序变化;
- **V2 目标(加分项,时间允许则完成)**:
  1. 专题地图出图(带图例、比例尺、指北针的成图输出)。

### 2.2 用户特点

| 用户类型 | 特点 | 主要操作 |
|---|---|---|
| 规划管理人员 | 熟悉业务但非 GIS 专业 | 浏览现状、动画观看变化、查询行政区统计 |
| 科研人员 | 熟悉 GIS 与土地利用研究 | 多年份对比、框选统计、导出数据、查看长时序变化 |
| 公众 | 无 GIS 基础 | 地图浏览、动画直观了解城市变化 |
| 系统管理员 | 具备数据库基础 | 数据更新(V1 阶段通过数据库维护脚本完成,无在线管理界面) |

对用户界面的一般要求:全中文界面、操作直观,无 GIS 基础的用户经简单提示即可完成主要操作。

### 2.3 运行环境

| 层次 | 运行环境 |
|---|---|
| 服务器 | Windows 10/11 桌面级环境;PostgreSQL 17 + PostGIS 3.6 空间数据库;Python 3.12 + FastAPI 后端 |
| 客户端 | Chrome / Edge 等现代浏览器(支持 WebGL 与 Canvas),无插件要求 |
| 网络 | 局域网或本机部署即可运行;如需公网访问可部署到云服务器 |

### 2.4 条件与限制

1. 原始数据为 30 m 分辨率栅格,单期武汉市范围约数百万像元;平台采用**双轨制**:展示层由前端直渲染 COG 栅格(30 m 原始分辨率,不提供传统瓦片地图服务),统计层由聚合网格入库支撑(细节见 3.3.3);
2. 平台定位为"展示 + 统计查询"型系统,**不包含**在线编辑地类、变更土地图斑等功能;数据更新由系统管理员通过维护脚本离线完成;
3. 面积统计以像元累计为基准(30 m × 30 m = 900 m²/像元),与实地测量存在固有误差,统计结果仅供宏观分析参考;
4. 平台展示的年份由数据源决定(CLCD 年度序列的代表年份),平台不负责生产新一期数据;后续新增年份只需补充数据并入库,不改动系统代码;
5. 武汉市中心(约 114.3°E)位于 UTM 49N 带东缘,该坐标系下投影变形相对较大,统计面积存在相应系统误差;坐标系由数据源决定,平台不改变数据坐标系。

## 3 需求规定

### 3.1 功能需求

功能需求以 FR(Functional Requirement)编号,每个需求按"描述、输入、处理、输出、验收准则、优先级"六要素描述。验收准则为可测试的量化标准,用于第 6 周系统测试阶段的逐项验收。

#### FR-01 地图浏览

- **描述**:用户进入系统后看到以武汉市为中心的地图窗口,可缩放、平移浏览底图。
- **输入**:鼠标/触控板的拖拽、滚轮缩放、缩放按钮点击。
- **处理**:前端地图引擎(Leaflet)加载底图图层;用户操作触发地图视图更新。
- **输出**:地图窗口实时刷新,显示底图及叠加的图层;地图比例尺随缩放联动。
- **验收准则**:打开系统 5 秒内地图以武汉市为中心完成显示;缩放、平移操作即时响应(无 1 秒以上卡顿)。
- **优先级**:高(所有功能的基础)。

#### FR-02 土地利用图层加载与显示

- **描述**:系统加载并显示各期土地利用图层,各地类按统一配色渲染,并同步显示图例。
- **输入**:用户选择要显示的年份(平台配置的代表年份列表)。
- **处理**:
  1. 前端请求所选年份的展示文件(预处理后的 COG tif,静态托管);
  2. 前端用 georaster 图层渲染,按"地类编码 → 配色"映射上色;
  3. 渲染图例。
- **输出**:地图上叠加所选年份的土地利用图层(30 m 原始分辨率,各地类颜色区分明显),图例面板显示地类名称与配色;所有年份使用同一套配色,保证跨期颜色语义一致。
- **验收准则**:选择任一年份,图层在局域网环境下 5 秒内完成传输并渲染(COG 分层加载,缩小视图秒出);图例所示颜色与图层实际颜色一一对应。
- **优先级**:高。

#### FR-03 多期图层时间轴播放与卷帘对比

- **描述**:系统提供两种时空对比方式:
  1. **时间轴播放**:底部时间轴滑块含全部代表年份节点,可手动拖动或点击"播放"按钮按时间顺序自动逐期切换图层,形成土地利用变化动画;
  2. **卷帘对比**:选择任意两期叠置显示,拖动地图上的分割线,分割线两侧分别显示两期图层,用于精确定位变化区域。
- **输入**:时间轴拖动/播放按钮;卷帘模式下选择两期年份并拖动分割线。
- **处理**:前端管理各年份图层实例;时间轴播放按设定间隔(如 1.5 秒)顺序切换图层显隐;卷帘模式利用前端图层裁剪(两个半幅图层容器)实现分割显示。
- **输出**:时间轴播放时各年份图层按时间顺序循环展示,直观呈现城市扩张过程;卷帘模式下两期图层随分割线拖动同步露出,变化区域一目了然。
- **验收准则**:播放模式下各年份按顺序切换、间隔均匀、可随时暂停;卷帘拖动流畅(无 1 秒以上卡顿),分割线两侧显示的图层与所选年份一致。
- **优先级**:高(V1 核心卖点)。

#### FR-04 框选面积统计

- **描述**:用户在地图上绘制矩形(或多边形)范围,系统返回该范围内各地类的面积与占比。
- **输入**:用户绘制的空间范围(矩形两个角点坐标,或依次点击的多边形顶点序列)。
- **处理**:
  1. 前端将范围几何(GeoJSON,WGS84)与年份参数提交后端;
  2. 后端将几何转换为数据坐标系(EPSG:32649),与所选年份的网格数据做空间相交计算(PostGIS 空间函数);
  3. 按地类编码分组汇总像元数,换算面积(像元数 × 900 m²)与占比;
  4. 返回结果。
- **输出**:统计结果表格(地类名称、编码、面积(公顷,附平方公里换算)、占比),在结果面板展示,可导出 CSV,并联动统计图表(FR-07)。
- **验收准则**:绘制 10 km × 10 km 矩形查询,2 秒内返回结果;返回的面积与用原始栅格独立统计的结果误差不超过 1%。
- **优先级**:高。

#### FR-05 行政区面积统计

- **描述**:用户选择一个行政区(武汉市 13 个辖区),系统返回该行政区内各地类的面积与占比;支持查看该行政区在全部年份的面积变化序列。
- **输入**:用户选择行政区(下拉列表,武汉市 13 个辖区)与年份(或"全部年份")。
- **处理**:
  1. 后端以行政区边界(面几何)与对应年份网格做空间相交;
  2. 按地类分组汇总像元数并换算面积;
  3. 若选"全部年份",则对全部年份分别执行并合并为时间序列结果。
- **输出**:所选行政区各地类面积统计表;选择全部年份时输出长时序对比表,并联动长时序图表(FR-07)。
- **验收准则**:查询任一辖区 2 秒内返回结果;全部年份对比表数据与框选同一区域的结果一致(交叉验证)。
- **优先级**:高。

#### FR-06 统计结果导出

- **描述**:用户可将任意一次统计结果导出为 CSV 文件,便于在 Excel 等工具中进一步处理。
- **输入**:用户点击"导出"按钮(当前统计结果随请求携带)。
- **处理**:前端将当前统计结果与查询条件一并提交后端;后端将结果组织为 CSV 格式(UTF-8 带 BOM,Excel 直接打开不乱码),以文件下载方式返回。该接口无状态,不同用户的并发导出互不影响。
- **输出**:浏览器下载 CSV 文件。
- **验收准则**:导出的 CSV 用 Excel 打开中文与数值均正常;内容与页面展示的统计表完全一致。
- **优先级**:中。

#### FR-07 长时序面积变化图表

- **描述**:平台的**核心分析功能**,以图表形式呈现:(1) **长时序面积变化折线**:选择区域(框选或行政区)与关注的地类(可多选),展示该地类面积在全部年份上的变化曲线,如"江岸区建设用地面积 2000-2023 年变化";(2) 当前查询的各地类面积柱状图。
- **输入**:统计查询结果(自动联动),或用户选择关注的地类与图表类型。
- **处理**:前端使用 ECharts 渲染图表;折线数据来自长时序统计接口(API-07,支持按地类过滤),柱状图数据来自当前查询结果。
- **输出**:交互式图表(悬浮显示数值,可切换地类);折线图展示所选地类在全部年份的面积变化趋势,图表与统计表格数据一致。
- **验收准则**:折线图正确展示所选地类在全部年份的面积变化;图表数值与表格逐项一致。
- **优先级**:高(平台核心功能)。

#### FR-08 专题地图出图(V2)

- **描述**:一键生成带图框、图例、比例尺、指北针的专题地图图片(PNG,300 dpi)。
- **输入**:用户选择年份与出图范围(当前视图)。
- **处理**:后端渲染专题图(复用聚合网格渲染逻辑)生成高分辨率 PNG。
- **输出**:浏览器下载 PNG 成图。
- **验收准则**:成图包含图框、图例、比例尺、指北针四要素;图例配色与前端一致。
- **优先级**:低(加分项)。

### 3.2 非功能需求

#### 3.2.1 性能需求

| 指标 | 要求 |
|---|---|
| 统计查询响应时间 | 常规查询(框选/行政区)在 2 秒内返回结果 |
| 图层加载时间 | 单期展示文件(COG tif)在局域网环境下 5 秒内完成传输并渲染 |
| 动画与交互流畅度 | 时间轴播放、卷帘拖动无 1 秒以上卡顿 |
| 并发能力 | 支持 5 个用户同时查询无明显卡顿(课程演示场景) |

#### 3.2.2 可靠性需求

1. 数据库连接失败、后端异常时,前端给出中文错误提示,不出现白屏或无响应;
2. 用户输入非法(空范围、范围超出数据区)时,系统给出明确提示而非崩溃;
3. 统计结果与栅格数据一致性:入库统计结果须与原始栅格像元统计一致(以独立脚本校验,误差不超过 1%)。

#### 3.2.3 易用性需求

1. 界面全中文,核心操作(选年份、画框、查统计)不超过 3 步;
2. 首次使用无需培训,界面提供必要的操作提示文字;
3. 图例、配色在不同年份间保持一致,避免用户混淆。

#### 3.2.4 安全性需求

1. 数据库访问使用受限账号,不暴露超级用户;
2. 后端所有空间查询采用参数化方式,防范 SQL 注入;
3. 系统以查询展示为主,不提供面向公网的写操作接口(V1 阶段)。

#### 3.2.5 可维护性与可扩展性需求

1. 前后端分离,接口以 REST API 定义,接口无状态,便于独立开发与测试;
2. 代码全程 Git + GitHub 版本管理,提交记录完整;
3. 地类编码、配色、行政区等配置集中管理,新增年份数据只增加配置项,不改动业务代码;
4. 代码注释遵循"教学注释"规范:每个模块、关键函数说明意图,便于后继开发者(面试官)审阅。

### 3.3 数据需求

#### 3.3.1 数据源

| 数据 | 说明 |
|---|---|
| 土地利用栅格 | CLCD 中国年度土地覆盖数据集(1985-2023):30 m 分辨率,年度更新,原始分类 9 类(农田、森林、灌木、草地、水域、冰雪、裸地、不透水面、湿地);按 5 年间隔选取代表年份入库(候选:2000/2005/2010/2015/2020/2023,具体清单见第 5 章 OP-04),经武汉范围裁剪、重投影(EPSG:32649)、9 类映射 7 类后入库;无效值(NoData)像元剔除,不计入统计 |
| 行政区划 | 武汉市 13 个辖区边界矢量数据(面),坐标系需与栅格统一(EPSG:32649);**获取方案见第 5 章未决问题** |
| 在线底图 | 地图窗口的参考底图(瓦片服务),**获取方案见第 5 章未决问题** |

#### 3.3.3 数据组织(入库方案)

平台对原始 30 m 栅格做**双轨处理**,展示与统计分离:

**展示轨(直渲染)**:各期栅格经裁剪(武汉范围)、重投影(WGS84)、COG 化(云优化 GeoTIFF)后,由前端直接加载渲染(georaster 图层),保持 30 m 原始分辨率,无需网格化;单期展示文件约数 MB,局域网传输无压力。

**统计轨(聚合入库)**:同一原始栅格按规则网格(1~2 km,具体粒度在第 4 周实现时经性能 POC 实测后确定)聚合统计每个网格内各地类的像元数,写入 PostGIS 空间表,支撑空间统计查询。处理步骤:

1. 用 Python(rasterio)读取各期栅格;
2. 按规则网格聚合统计每个网格内各地类的像元数;
3. 无效值(NoData)像元在聚合时剔除,不计入任何统计;
4. 聚合结果(网格几何 + 各地类像元数)写入 PostGIS 空间表;
5. 网格几何以 EPSG:32649 存储;对外传输统一由**后端**转换为 WGS84(EPSG:4326),前端只处理经纬度,不承担任何坐标系换算;
6. 行政区边界数据同时入库。

**双轨口径一致性**:两轨均源自同一原始栅格,统计结果与地图展示天然一致;入库统计结果以独立脚本与原始栅格对比校验(见 3.2.2)。

**设计定位(矢量瓦片口径)**:聚合网格在思路上与矢量瓦片(Vector Tiles)一致——都是"面向 Web 展示的分级聚合",本方案中聚合网格专职统计查询,展示交给直渲染轨道;V2 可平滑升级为 PostGIS + pg_tileserv 发布标准 MVT 瓦片,服务海量数据与任意缩放级别。

数据入库与校验属开发阶段任务,本平台交付时须**随系统提供已入库的数据库**,使系统开箱即可运行。

### 3.4 接口需求

#### 3.4.1 后端 REST API

| 编号 | 接口 | 方法 | 说明 |
|---|---|---|---|
| API-01 | /api/layers | GET | 返回可用年份图层列表及元数据(年份、来源、说明) |
| API-02 | /api/layers/{year}/tif | GET | 返回某年份展示文件(COG tif,静态托管)的访问地址与元数据(范围、分辨率、地类说明) |
| API-03 | /api/stats/geometry | POST | 提交框选/任意几何(GeoJSON)与年份,返回各地类面积统计 |
| API-04 | /api/stats/region | GET | 按行政区名 + 年份(或"全部年份")返回面积统计 |
| API-05 | /api/stats/export | POST | 无状态导出:请求体携带查询条件与统计结果,返回 CSV 文件(UTF-8 带 BOM) |
| API-06 | /api/regions | GET | 返回武汉市 13 个辖区列表(供下拉选择) |
| API-07 | /api/stats/timeseries | GET | 返回指定行政区(或几何范围)在全部年份的各地类面积时间序列,支持按地类过滤参数(land_type),供 FR-07 长时序图表使用 |

约定:所有接口返回 JSON(API-05 返回 CSV 文件除外);错误时返回 `{code, message}` 结构,前端据此提示用户;几何坐标统一用 WGS84(EPSG:4326)经纬度传输,由后端转换到数据坐标系(EPSG:32649)计算,前端不处理坐标系换算;全部接口无状态,服务器不保存"上一次查询"等会话数据。

#### 3.4.2 数据库接口

- 空间数据库:PostgreSQL 17 + PostGIS 3.6,数据库名 `wuhan_landuse`;
- 后端通过 psycopg(或等效驱动)访问,全部 SQL 参数化;
- 空间计算依赖 PostGIS 函数(ST_Intersects、ST_Transform 等),不自行实现几何运算;
- 网格表与行政区表建立空间索引(GiST),保证查询性能(对应 3.2.1 性能指标)。

#### 3.4.3 用户接口(界面要素)

1. 地图窗口(占据界面主体);
2. 年份选择栏(代表年份)与时间轴(滑块 + 播放按钮);
3. 图例面板(随图层联动);
4. 查询工具条:框选按钮、卷帘对比按钮、行政区下拉选择、统计按钮;
5. 结果面板:统计表格 + 图表(柱状图/时间序列折线图)+ 导出按钮。
