## 1 引言

### 1.1 编写目的

本文档是《武汉市土地利用时空信息服务平台》的软件需求规格说明书(Software Requirements Specification,SRS),用于明确该软件"做什么"。本文档的预期读者包括:

- **开发人员**(作者本人):作为设计、编码和测试的依据;
- **课程教师**:作为评判该课程设计是否满足考核要求的依据;
- **潜在用户**(城市规划、土地管理部门人员):了解软件功能是否符合业务需要。

### 1.2 项目背景

土地利用/覆被变化(LUCC)是城市发展研究的基础数据。武汉市作为中部特大城市,2000 年代以来经历了快速城镇化,建设用地扩张、耕地与林地缩减等变化显著。当前,武汉市已积累多期土地利用数据(2003、2005、2010、2013 年四期 30 m 分辨率栅格),但这些数据以栅格文件形式存放,查看和统计需要使用专业桌面 GIS 软件,普通用户难以直接使用。

本平台针对上述问题,开发一套 **Web 形态的土地利用时空信息服务平台**,使用户无需安装任何专业软件,通过浏览器即可:

1. 浏览武汉市多期土地利用图;
2. 切换、对比不同时期的土地利用状况;
3. 对任意区域(框选范围或行政区)进行各地类面积统计查询。

平台同时为 PLUS 模型模拟的未来土地利用情景(加分功能)提供展示与统计能力,支撑城市扩张模拟研究的成果发布。

### 1.3 术语定义

| 术语 | 说明 |
|---|---|
| 土地利用栅格 | 用规则网格(像元)记录地表覆被类型的空间数据,每个像元值为地类编码 |
| 像元 | 栅格数据的最小单元,本文档数据中一个像元代表地面 30 m × 30 m 范围 |
| 地类编码 | 用地类型的数字编号(1~7),与地类名称一一对应 |
| 空间数据库 | 支持空间数据类型(点、线、面)和空间运算的数据库,本平台采用 PostgreSQL + PostGIS |
| PostGIS | PostgreSQL 的空间扩展,提供空间数据类型与空间分析函数 |
| WebGIS | 基于 Web 的地理信息系统,浏览器端完成地图显示与交互 |
| 行政区统计 | 以行政区划边界(面)为范围,统计该范围内各地类面积 |
| 框选统计 | 用户在地图上手绘一个矩形(或多边形),统计该范围内各地类面积 |
| PLUS 模型 | 斑块生成土地利用模拟模型(Patch-generating Land Use Simulation),用于模拟未来土地利用情景 |
| EPSG:32649 | 坐标参考系编码,即 UTM 投影 49 度带,武汉市栅格数据采用该坐标系 |

### 1.4 参考资料

1. GB/T 9385-2008 计算机软件需求规格说明规范;
2. 中华人民共和国国家标准 GB/T 21010-2017《土地利用现状分类》;

4. PLUS 模型官方文档(Liang X. et al., 2021, Computers, Environment and Urban Systems)。

## 2 任务概述

### 2.1 项目目标

开发一套可运行的 Web 时空信息服务平台,实现武汉市土地利用数据的在线浏览、多期对比与面积统计查询,并预留未来情景模拟结果的展示能力。具体目标按优先级分为两级:

- **V1 目标(及格线,必须完成)**:
  1. 网页地图浏览:加载武汉市底图,支持缩放、平移;
  2. 多期图层切换:加载 2003/2005/2010/2013 四期土地利用图层,可任意切换、并排对比;
  3. 面积统计查询:支持两种空间查询方式(框选范围、行政区),返回各地类面积、占比;
- **V2 目标(加分项,时间允许则完成)**:
  1. 加载 PLUS 模型模拟的未来土地利用图层;
  2. 用统计图表(ECharts)展示各地类面积的时间变化;
  3. 专题地图出图(带图例、比例尺的成图输出)。

### 2.2 用户特点

| 用户类型 | 特点 | 主要操作 |
|---|---|---|
| 规划管理人员 | 熟悉业务但非 GIS 专业 | 浏览现状、对比变化、查询行政区统计 |
| 科研人员 | 熟悉 GIS 与土地利用研究 | 多期对比、框选统计、导出数据 |
| 公众 | 无 GIS 基础 | 地图浏览、直观了解城市变化 |
| 系统管理员 | 具备数据库基础 | 数据更新、系统部署维护 |

对用户界面的一般要求:全中文界面、操作直观,无 GIS 基础的用户经简单提示即可完成主要操作。

### 2.3 运行环境

| 层次 | 运行环境 |
|---|---|
| 服务器 | Windows 10/11 桌面级环境;PostgreSQL 17 + PostGIS 3.6 空间数据库;Python 3.12 + FastAPI 后端 |
| 客户端 | Chrome / Edge 等现代浏览器(支持 WebGL 与 Canvas),无插件要求 |
| 网络 | 局域网或本机部署即可运行;如需公网访问可部署到云服务器 |

### 2.4 条件与限制

1. 原始数据为 30 m 分辨率栅格,单期约 2931 × 2931 像元;受 Web 传输与渲染能力限制,平台**不提供**全分辨率栅格的瓦片地图服务,而是将栅格数据按网格聚合统计后以矢量形式(GeoJSON)提供前端展示(细节见 3.3 数据需求);
2. 平台定位为"展示 + 统计查询"型系统,**不包含**在线编辑地类、变更土地图斑等功能;
3. 面积统计以像元累计为基准(30 m × 30 m = 900 m²/像元),与实地测量存在固有误差,统计结果仅供宏观分析参考;
4. 四期数据年份(2003/2005/2010/2013)为数据本身决定,平台不负责生产新一期数据;未来情景数据由 PLUS 模型离线模拟后导入。

## 3 需求规定

### 3.1 功能需求

功能需求以 FR(Functional Requirement)编号,每个需求按"描述、输入、处理、输出、优先级"五要素描述。

#### FR-01 地图浏览

- **描述**:用户进入系统后看到以武汉市为中心的地图窗口,可缩放、平移浏览底图。
- **输入**:鼠标/触控板的拖拽、滚轮缩放、缩放按钮点击。
- **处理**:前端地图引擎(Leaflet)加载底图图层;用户操作触发地图视图更新。
- **输出**:地图窗口实时刷新,显示底图及叠加的图层;地图比例尺随缩放联动。
- **优先级**:高(所有功能的基础)。

#### FR-02 土地利用图层加载与显示

- **描述**:系统加载并显示各期土地利用图层,各地类按统一配色渲染,并显示图例。
- **输入**:用户选择要显示的年份(2003/2005/2010/2013)。
- **处理**:
  1. 前端向后端请求所选年份的图层数据(GeoJSON 网格);
  2. 后端从空间数据库读取该年份网格数据并返回;
  3. 前端按"地类编码 → 配色"映射渲染网格,并渲染图例。
- **输出**:地图上叠加所选年份的土地利用图层(各地类颜色区分明显),图例面板显示地类名称与配色。
- **优先级**:高。

#### FR-03 多期图层切换与对比

- **描述**:用户可以快速切换不同年份的图层,并支持两期图层并排(分屏)或叠置对比,直观观察土地利用变化。
- **输入**:用户选择目标年份、切换操作或对比模式。
- **处理**:前端管理多个年份图层实例;切换模式下只显示选中年份;对比模式下左右分屏各显示一期(联动缩放)。
- **输出**:所选年份图层正确显示;对比模式下两期图同步缩放、平移,便于目视判读变化。
- **优先级**:高(V1 核心卖点)。

#### FR-04 框选面积统计

- **描述**:用户在地图上绘制矩形(或多边形)范围,系统返回该范围内各地类的面积与占比。
- **输入**:用户绘制的空间范围(矩形两个角点坐标,或依次点击的多边形顶点序列)。
- **处理**:
  1. 前端将范围几何(GeoJSON)与年份参数提交后端;
  2. 后端将几何转换为数据坐标系(EPSG:32649),与所选年份的网格数据做空间相交计算;
  3. 按地类编码分组汇总像元数,换算面积(像元数 × 900 m²)与占比;
  4. 返回结果。
- **输出**:统计结果表格(地类名称、编码、面积(公顷/平方公里)、占比),在结果面板展示,可导出 CSV。
- **优先级**:高。

#### FR-05 行政区面积统计

- **描述**:用户选择一个行政区(武汉市辖区),系统返回该行政区内各地类的面积与占比;支持查看该行政区在四期的面积变化。
- **输入**:用户选择行政区(下拉列表或点击地图)与年份(或"全部年份")。
- **处理**:
  1. 后端以行政区边界(面几何)与对应年份网格做空间相交;
  2. 按地类分组汇总像元数并换算面积;
  3. 若选"全部年份",则对四期分别执行并合并结果。
- **输出**:所选行政区各地类面积统计表;选择全部年份时输出四期对比表(供变化分析)。
- **优先级**:高。

#### FR-06 统计结果导出

- **描述**:用户可将任意一次统计结果导出为 CSV 文件,便于在 Excel 等工具中进一步处理。
- **输入**:用户点击"导出"按钮。
- **处理**:后端将当前统计结果组织为 CSV 格式(UTF-8 带 BOM,Excel 可直接打开不乱码),以文件下载方式返回。
- **输出**:浏览器下载 CSV 文件。
- **优先级**:中。

#### FR-07 地类图例与说明

- **描述**:系统始终显示当前图层对应的图例(地类名称 + 配色),并提供地类编码说明。
- **输入**:无(随图层自动更新)。
- **处理**:前端根据当前图层年份从配置中读取地类配色表并渲染。
- **输出**:图例面板;所有年份使用同一套配色,保证跨期对比时颜色语义一致。
- **优先级**:中。

#### FR-08 未来情景图层展示(V2)

- **描述**:加载并展示 PLUS 模型模拟的未来年份土地利用图层(如 2033 年),与历史期图层同框架浏览、统计。
- **输入**:用户选择"模拟情景"年份。
- **处理**:与 FR-02 相同,数据为 PLUS 模拟结果导入的图层。
- **输出**:模拟情景图层叠加显示,可参与面积统计。
- **优先级**:低(加分项)。

#### FR-09 统计图表展示(V2)

- **描述**:用柱状图/折线图展示各地类面积随年份的变化趋势(含模拟情景)。
- **输入**:用户选择图表类型与地类(或多地类)。
- **处理**:前端调用统计接口获取多期面积序列,用 ECharts 渲染图表。
- **输出**:交互式图表(悬浮显示数值,可切换地类)。
- **优先级**:低(加分项)。

#### FR-10 专题地图出图(V2)

- **描述**:一键生成带图框、图例、比例尺、指北针的专题地图图片(PNG,300 dpi)。
- **输入**:用户选择年份与出图范围(当前视图)。
- **处理**:后端渲染专题图(复用数据渲染逻辑)生成高分辨率 PNG。
- **输出**:浏览器下载 PNG 成图。
- **优先级**:低(加分项)。

### 3.2 非功能需求

#### 3.2.1 性能需求

| 指标 | 要求 |
|---|---|
| 统计查询响应时间 | 常规查询(框选/行政区)在 2 秒内返回结果 |
| 图层加载时间 | 单期图层数据在局域网环境下 3 秒内完成传输并渲染 |
| 并发能力 | 支持 5 个用户同时查询无明显卡顿(课程演示场景) |

#### 3.2.2 可靠性需求

1. 数据库连接失败、后端异常时,前端给出中文错误提示,不出现白屏或无响应;
2. 用户输入非法(空范围、范围超出数据区)时,系统给出明确提示而非崩溃;
3. 统计结果与栅格数据一致性:入库统计结果须与原始栅格像元统计一致(以独立脚本校验)。

#### 3.2.3 易用性需求

1. 界面全中文,核心操作(选年份、画框、查统计)不超过 3 步;
2. 首次使用无需培训,界面提供必要的操作提示文字;
3. 图例、配色在不同年份间保持一致,避免用户混淆。

#### 3.2.4 安全性需求

1. 数据库访问使用受限账号,不暴露超级用户;
2. 后端所有空间查询采用参数化方式,防范 SQL 注入;
3. 系统以查询展示为主,不提供面向公网的写操作接口(V1 阶段)。

#### 3.2.5 可维护性与可扩展性需求

1. 前后端分离,接口以 REST API 定义,便于独立开发与测试;
2. 代码全程 Git + GitHub 版本管理,提交记录完整;
3. 地类编码、配色、行政区等配置集中管理,新增年份数据只增加配置项,不改动业务代码;
4. 代码注释遵循"教学注释"规范:每个模块、关键函数说明意图,便于后继开发者(面试官)审阅。

### 3.3 数据需求

#### 3.3.1 数据源

| 数据 | 说明 |
|---|---|
| 土地利用栅格 | 武汉市四期:2003、2005、2010、2013;30 m 分辨率,2931 × 2931 像元;EPSG:32649(UTM 49N);地类编码 1~7(另有 0/255 无效值) |
| 行政区划 | 武汉市行政区边界矢量数据(面),坐标系需与栅格统一(EPSG:32649) |
| 模拟情景数据(可选) | PLUS 模型输出的未来土地利用栅格(与历史期同规格) |

#### 3.3.2 地类编码字典

| 编码 | 地类名称 | 显示配色(RGB) | 说明 |
|---|---|---|---|
| 1 | 耕地 | 250, 217, 102(金黄) | 水田、旱地等耕作土地 |
| 2 | 林地 | 33, 120, 54(深绿) | 有林地、灌木林等 |
| 3 | 草地 | 158, 204, 89(浅绿) | 天然草地、人工草地 |
| 4 | 水体 | 38, 115, 191(蓝) | 河流、湖泊、坑塘 |
| 5 | 建设用地 | 217, 56, 56(红) | 城镇村、工矿、交通用地 |
| 6 | 未利用地 | 166, 166, 166(灰) | 沙地、裸地等 |
| 7 | 湿地 | 51, 166, 166(青) | 沼泽、滩涂等 |

#### 3.3.3 数据组织(入库方案)

受 Web 传输限制,平台不直接传输 30 m 全分辨率栅格,而是**预处理入库**:

1. 用 Python(rasterio)读取各期栅格;
2. 按规则网格(如 500 m × 500 m)聚合统计每个网格内各地类的像元数;
3. 聚合结果(网格几何 + 各地类像元数)写入 PostGIS 空间表,网格几何以 EPSG:32649 存储,前端展示时转换为 WGS84;
4. 行政区统计所需的行政区边界同时入库。

数据入库与校验属开发阶段任务,本平台交付时须**随系统提供已入库的数据库**,使系统开箱即可运行。

### 3.4 接口需求

#### 3.4.1 后端 REST API(V1)

| 编号 | 接口 | 方法 | 说明 |
|---|---|---|---|
| API-01 | /api/layers | GET | 返回可用年份图层列表及元数据(年份、来源、说明) |
| API-02 | /api/layers/{year}/grid | GET | 返回某年份的聚合网格 GeoJSON(含各地类像元数) |
| API-03 | /api/stats/geometry | POST | 提交框选/任意几何(GeoJSON)与年份,返回各地类面积统计 |
| API-04 | /api/stats/admin | GET | 按行政区名 + 年份(或全部年份)返回面积统计 |
| API-05 | /api/stats/export | GET/POST | 将最近一次统计结果导出为 CSV |
| API-06 | /api/admin | GET | 返回行政区列表(供下拉选择) |

约定:所有接口返回 JSON;错误时返回 `{code, message}` 结构,前端据此提示用户;几何坐标统一用 WGS84(EPSG:4326)经纬度传输,由后端转换到数据坐标系计算。

#### 3.4.2 数据库接口

- 空间数据库:PostgreSQL 17 + PostGIS 3.6,数据库名 `wuhan_landuse`;
- 后端通过 psycopg(或等效驱动)访问,全部 SQL 参数化;
- 空间计算依赖 PostGIS 函数(ST_Intersects、ST_Transform、ST_Union 等),不自行实现几何运算。

#### 3.4.3 用户接口(界面要素)

1. 地图窗口(占据界面主体);
2. 年份切换栏(2003/2005/2010/2013 按钮或下拉);
3. 图例面板(随图层联动);
4. 查询工具条:框选按钮、行政区下拉选择、统计按钮;
5. 结果面板:统计表格 + 导出按钮;
6. 对比模式开关(分屏/叠置)。

## 4 运行环境规定

### 4.1 硬件设备

| 项目 | 最低配置 |
|---|---|
| 服务器 | 普通 PC/笔记本:4 核 CPU、8 GB 内存、10 GB 可用磁盘 |
| 客户端 | 能运行现代浏览器的任意设备(含手机,界面按桌面优先设计) |

### 4.2 支持软件

| 软件 | 版本 | 用途 |
|---|---|---|
| Windows | 10/11 | 服务器操作系统(亦可 Linux) |
| PostgreSQL | 17.x | 数据库 |
| PostGIS | 3.6.x | 空间扩展 |
| Python | 3.12 | 后端语言 |
| FastAPI | 0.11x | Web 后端框架 |
| Node.js | 24.x | 前端构建工具链 |
| Vue 3 | 3.x | 前端框架 |
| Leaflet | 1.9.x | 地图引擎 |

### 4.3 接口与部署形态

- 前后端通过 HTTP 接口通信;数据库仅后端访问,不直接暴露给浏览器;
