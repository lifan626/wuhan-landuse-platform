## 2 总体设计

### 2.1 系统架构

系统采用 **B/S 三层架构**(浏览器/服务器),前后端分离:

```
┌─────────────────────┐
│  浏览器(前端)        │  Vue 3 + Leaflet + ECharts
│  - 地图/时间轴/图表   │  (静态资源,由后端托管)
└──────────┬──────────┘
           │ HTTP(JSON / GeoJSON / CSV)
┌──────────▼──────────┐
│  Web 后端(FastAPI)   │  图层服务 / 统计服务 / 导出服务
│  - 参数校验与坐标转换 │  (Python 3.12)
└──────────┬──────────┘
           │ SQL(参数化,psycopg)
┌──────────▼──────────┐
│  空间数据库           │  PostgreSQL 17 + PostGIS 3.6
│  - 聚合网格/行政区     │  GiST 空间索引
└─────────────────────┘
```

设计要点:

1. **数据库只由后端访问**,浏览器不直连数据库(安全与解耦);
2. **坐标转换全部在后端完成**:数据以 EPSG:32649 存储,对外传输统一 WGS84(EPSG:4326),前端只处理经纬度;
3. **接口全部无状态**,服务器不保存会话与"上一次查询";
4. 前端静态资源由后端托管,部署形态为"一条命令启动,浏览器即用"。

### 2.2 技术选型与理由

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | Vue 3(组合式 API) | 国内岗位主流框架;组件化适合地图+面板的多区域界面 |
| 地图引擎 | Leaflet 1.9 | 轻量、学习曲线平缓;聚合网格为矢量多边形,Leaflet 渲染足够;不引入瓦片服务依赖 |
| 图表库 | ECharts 5 | 国内事实标准;折线图/柱状图开箱即用 |
| 后端框架 | FastAPI | Python 生态与空间数据处理栈(rasterio/geopandas)天然衔接;自动生成 API 文档 |
| 空间数据库 | PostgreSQL 17 + PostGIS 3.6 | 空间 SQL 能力(空间索引、ST_Intersects 等)是 WebGIS 后端标配;招聘岗位明确要求"地图数据库建设"能力 |
| 数据入库 | Python + rasterio | 读取 GeoTIFF、网格聚合统计的成熟工具链 |

### 2.4 关键流程设计

#### 2.4.1 图层加载流程(FR-02)

1. 用户选择年份 → 前端调用 `GET /api/layers/{year}/grid?bbox=...`;
2. 后端按年份(必要时按视口 bbox)查询网格表,将几何从 EPSG:32649 转换为 WGS84,组装 GeoJSON 返回;
3. 前端将 GeoJSON 渲染为 Leaflet 多边形图层,按地类编码应用统一配色,刷新图例。

#### 2.4.2 框选统计流程(FR-04)

1. 前端将绘制的矩形/多边形(WGS84 GeoJSON)POST 至 `/api/stats/geometry`;
2. 后端将几何转为 EPSG:32649,执行空间相交聚合 SQL(见 4.4),按地类汇总像元数;
3. 像元数 × 900 m² 换算面积,返回各地类面积与占比;
4. 前端在结果面板渲染表格,联动 ECharts 柱状图(FR-07)。

#### 2.4.3 长时序统计流程(FR-05/FR-07)

1. 用户选行政区 + "全部年份"(或框选后查看时间序列);
2. 后端执行按年份分组的时间序列 SQL(见 4.4),返回各地类逐年面积;
3. 前端 ECharts 渲染折线图:横轴年份、纵轴面积,支持按地类筛选。

## 3 前端模块设计

### 3.1 组件职责与数据流

各组件职责见 2.3 目录注释。组件间数据流采用 Vue 3 组合式 API 的 props/emit 单向数据流,不引入全局状态库(规模不需要):

- **App.vue** 持有全局状态:当前年份、当前统计结果、对比模式;
- **MapPanel** 接收年份,负责图层的加载与显隐;向 App 上报框选几何;
- **TimelineBar** 控制年份切换与播放(定时器逐期切换,可暂停);
- **ResultPanel / ChartPanel** 接收统计结果,负责表格与图表渲染。

### 3.2 关键实现要点

#### 3.2.1 时间轴播放(FR-03)

- 年份数组来自 `GET /api/layers` 的返回,按升序排列;
- "播放"按钮启动定时器(setInterval,间隔 1.5 s),顺序切换当前年份;到末尾回绕到开头循环;
- 切换年份只改状态,图层加载走统一逻辑,保证行为一致。

#### 3.2.2 卷帘对比(FR-03)

- 实现方式:两个半幅图层容器上下叠放(Leaflet 支持 SVG 裁剪路径),上层显示 A 期、下层显示 B 期;
- 拖动分割线更新裁剪路径,两期图层随分割线同步露出;
- 仅两期图层实例参与卷帘,退出卷帘模式即销毁临时图层。

#### 3.2.3 图层渲染与配色

- 配色表集中配置于 `config/`(地类编码 → 颜色、名称),全端唯一来源;
- 聚合网格渲染为 Leaflet `Polygon`,按网格内主导地类(像元数最多者)上色;
- 图例面板读取同一配色表生成,保证图层与图例永远一致。

#### 3.2.4 图表渲染(FR-07)

- 柱状图:当前查询结果各地类面积;
- 折线图:长时序接口返回的逐年数据,支持勾选地类显示/隐藏;
- 图表与表格共用同一份数据源,保证数值一致。

### 3.3 前端错误处理

- 统一封装 fetch:非 2xx 状态时读取后端 `{code, message}`,以中文提示条展示,页面不白屏;
- 查询返回空结果时,结果面板显示"该范围内无有效数据",而非空表格。

## 4 后端模块设计

### 4.1 分层与职责

| 层 | 文件 | 职责 |
|---|---|---|
| 路由层 | routers/*.py | 定义 REST 接口,校验请求参数,调用业务层 |
| 业务层 | services/landuse.py | 组装 SQL、执行查询、坐标转换、结果换算(像元→面积) |
| 数据访问 | db.py | 连接池管理、查询执行 |

### 4.2 数据库连接

- 使用 psycopg(3.x)连接池;
- 连接参数集中于 config.py:主机 localhost、端口 5432、库 wuhan_landuse、受限账号(不使用超级用户);
- 所有 SQL 一律参数化(占位符传参),杜绝字符串拼接。

### 4.3 坐标转换约定

- 入库与存储:EURG:32649(与数据源一致);
- 对外传输:WGS84(EPSG:4326);
- 转换函数:PostGIS `ST_Transform`,转换一律在 SQL 内完成(读取时转出、写入时转入);
- 前端收到的 GeoJSON 中几何一律为经纬度。

### 4.4 核心 SQL 设计

**按年份取网格(API-02)**:

```sql
SELECT ST_AsGeoJSON(ST_Transform(geom, 4326)) AS geom, c1, c2, c3, c4, c5, c6, c7
FROM landuse_grid
WHERE year = %s;
-- 携带 bbox 参数时追加:
--   AND geom && ST_Transform(ST_MakeEnvelope(minx, miny, maxx, maxy, 4326), 32649)
```

**框选统计(API-03)**:

```sql
SELECT
  SUM(c1) AS s1, SUM(c2) AS s2, SUM(c3) AS s3, SUM(c4) AS s4,
  SUM(c5) AS s5, SUM(c6) AS s6, SUM(c7) AS s7
FROM landuse_grid
WHERE year = %s
  AND geom && ST_Transform(%s::geometry, 32649)      -- 包围盒粗筛(走 GiST 索引)
  AND ST_Intersects(geom, ST_Transform(%s::geometry, 32649));  -- 精确相交
```

**行政区统计(API-04)**:先按名称查行政区边界,再以上述相同方式执行。

**长时序统计(API-07)**:

```sql
SELECT year, SUM(c1) AS s1, ..., SUM(c7) AS s7
FROM landuse_grid
WHERE geom && %s AND ST_Intersects(geom, %s)   -- 区域几何(EPSG:32649)
GROUP BY year
ORDER BY year;
```

**行政区列表(API-06)**:`SELECT name FROM regions ORDER BY name;`

### 4.5 面积换算

- 面积(公顷)= 像元数 × 900 m² ÷ 10000;
- 换算在后端业务层完成,接口返回数值字段,前端不做单位计算。

## 5 数据库设计

### 5.1 数据库与扩展

- 数据库名:`wuhan_landuse`;
- 扩展:postgis(已启用),无需其他扩展;
- 字符集:UTF8。

### 5.2 表结构设计

#### 5.2.1 landuse_grid(土地利用聚合网格表)

| 字段 | 类型 | 说明 |
|---|---|---|
| id | serial 主键 | 网格唯一标识 |
| year | smallint 非空 | 年份(代表年份,如 2000/2005/2010/2015/2020/2023) |
| geom | geometry(Polygon, 32649) | 网格几何(1~2 km 规则网格,数据坐标系) |
| c1 ~ c7 | integer 非空 默认 0 | 该网格内 1~7 类地类的像元数(无效值已剔除) |
| total | integer 非空 | 有效像元总数(c1+...+c7) |

约束与索引:

```sql
CHECK (total = c1 + c2 + c3 + c4 + c5 + c6 + c7)
CREATE INDEX idx_landuse_year ON landuse_grid (year);
CREATE INDEX idx_landuse_geom ON landuse_grid USING GIST (geom);
```

**设计说明**:
- 采用**宽表**结构(一行一个网格,7 列像元数),一次查询可同时取到全部地类,避免 7 次 GROUP BY;
- 宽表一行即"某年某网格的完整地类构成",与"某类用地长时序变化"的查询模式(按区域聚合再按年份分组)匹配;
- 6 个代表年份 × 约 7.7 千~3.1 万个网格(按 1~2 km 粒度),总量约 5 万~20 万行,PostGIS 无压力。

#### 5.2.2 regions(行政区表)

| 字段 | 类型 | 说明 |
|---|---|---|
| id | serial 主键 | 区唯一标识 |
| name | text 非空唯一 | 区名(江岸区等 13 个辖区) |
| geom | geometry(MultiPolygon, 32649) | 行政区边界 |

索引:`CREATE INDEX idx_regions_geom ON regions USING GIST (geom);`

### 5.3 数据入库流程(database/ingest_grids.py)

```
原始 GeoTIFF(全国,30m,Albers)
   │  ① rasterio 读取
   ▼
裁剪武汉范围(按武汉边界缓冲外扩) → 重投影 EPSG:32649
   │  ② 9 类映射 7 类(森林+灌木→林地;冰雪+裸地→未利用地;其余一一对应)
   ▼
按规则网格(1~2 km)分组统计各地类像元数(剔除 NoData)
   │  ③ 批量写入
   ▼
landuse_grid 表(附 year 字段)
```

校验环节:入库后随机抽样 N 个网格,与原始栅格独立统计对比,误差必须为 0(聚合为精确运算),整体校验结果记录入库日志。

### 5.4 备份与交付

- 交付时导出数据库备份(`pg_dump -Fc wuhan_landuse > wuhan_landuse.dump`),随系统一并提交(五件套之"配套数据");
- 换机复现:恢复备份 → 启动后端 → 浏览器访问。

## 6 接口详细设计

通用约定(与需求文档 3.4.1 一致):全部无状态;几何一律 WGS84;错误返回 `{code, message}`;成功返回业务 JSON。

### 6.1 GET /api/layers

返回可用年份列表:

```json
{"layers": [{"year": 2000}, {"year": 2005}, {"year": 2010}, {"year": 2015}, {"year": 2020}, {"year": 2023}]}
```

### 6.2 GET /api/layers/{year}/grid

返回某年份聚合网格 GeoJSON(FeatureCollection)。Feature 属性含 7 类像元数;几何为 WGS84。支持 `?bbox=minx,miny,maxx,maxy`(视口裁剪)。

### 6.3 POST /api/stats/geometry

请求体:

```json
{"year": 2023, "geometry": {"type": "Polygon", "coordinates": [[[114.2,30.4], ...]]}}
```

响应:

```json
{"year": 2023, "items": [
  {"class": 1, "name": "耕地", "pixels": 12345, "area_ha": 1111.05, "ratio": 0.183},
  ...
], "total_area_ha": 6070.8}
```

### 6.4 GET /api/stats/region?name=江岸区&year=2023

单年份:结构同 6.3。`year=all` 时返回逐年份序列:

```json
{"region": "江岸区", "series": [
  {"year": 2000, "items": [...]}, {"year": 2005, "items": [...]}, ...
]}
```

### 6.5 POST /api/stats/export

请求体携带查询条件与统计结果(无状态),响应为 CSV 文件下载(UTF-8 带 BOM;表头:年份,地类,像元数,面积_公顷,占比_%)。

### 6.6 GET /api/regions

```json
{"regions": ["江岸区", "江汉区", "硚口区", "汉阳区", "武昌区", "青山区", "洪山区", "东西湖区", "汉南区", "蔡甸区", "江夏区", "黄陂区", "新洲区"]}
```

### 6.7 GET /api/stats/timeseries?geometry=...&land_type=5

按几何范围(或行政区)返回某地类(可选过滤)逐年面积:

```json
{"series": [{"year": 2000, "area_ha": 5230.1}, {"year": 2005, "area_ha": 6910.4}, ...]}
```

### 6.8 错误响应示例

```json
{"code": "INVALID_GEOMETRY", "message": "查询范围为空,请重新绘制"}
{"code": "DB_ERROR", "message": "数据库连接失败,请稍后重试"}
```

## 7 出错处理设计

| 场景 | 处理 |
|---|---|
| 数据库不可用 | 后端捕获连接异常,返回 DB_ERROR;前端提示"数据库连接失败,请稍后重试" |
| 非法几何(空范围/自相交) | 后端校验几何有效性(ST_IsValid),非法则返回 INVALID_GEOMETRY |
| 年份不存在 | 返回 YEAR_NOT_FOUND,前端年份控件以 /api/layers 返回值为准,避免出现该错误 |
| 查询范围超出数据区 | 正常返回空结果(全 0),前端提示"该范围内无有效数据" |
| 前端网络超时 | fetch 封装统一超时(10 s),提示用户重试 |
